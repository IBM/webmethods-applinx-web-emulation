3. Feature Integrity Checks

🎨 CSS Styling — InputFieldComponent & FieldComponent

SAFE

The [style]="getCss()" template binding is Angular Ivy's standard object-map style binding. The fix changed getCss() from returning a SafeStyle object (via bypassSecurityTrustStyle) to returning a plain {[key:string]:string} map. Angular Ivy natively accepts this type — no template change needed. The 18-property allowlist covers all IBM ApplinX screen attributes. The url() and expression() value guards block CSS injection. DomSanitizer import removed from both components — correct, it is no longer used.

⌨️ Keyboard Dispatch — KeyboardMappingService

SAFE

The hasOwnProperty guard blocks prototype-chain method names (constructor, __proto__, toString, etc.) from being dispatched dynamically. All real custom user-exit methods defined as own properties of the KeyboardMappingService instance still pass. The VALID_HOST_KEY regex /^\[([A-Z0-9+_]+)\]$/ covers standard ApplinX host keys like [ENTER], [PF1]–[PF24], [PA1]–[PA3], [ATTN], [CLEAR], [ROLLDN], [ROLLUP], [FIELD+]. Non-host-key strings (free text) are sent via the normal character path unaffected.

⚠️ Residual action: Verify VALID_HOST_KEY regex against deployed KeyboardMappings.json for all AS/400-specific key names. Keys with lowercase or special characters would be silently rejected — confirm against real deployment config.

🔐 OIDC Auth — OAuth2HandlerService & RouteGuardService

SAFE

The OIDC state fix only activates when route.queryParams.code is present. Non-OIDC login flows (direct username/password) do not enter the OIDC callback path. The state comparison is a strict string equality check; no regex or parsing is involved. State is written to sessionStorage before redirect and read back after callback — the window cannot be cross-origin manipulated. The redirectUri HTTPS-only validation rejects http: and non-URL strings before router.navigateByUrl(); standard ApplinX https:// URIs pass without issue.

🎬 Macro Recording & Playback — SharedService & MacroComponent

SAFE (with known limitation)

The pwdMask placeholder replaces window.btoa(value) for password field keystrokes during recording — this is functionally correct as macros must not store credentials. The JSON.parse fix for extracting userName from sessionStorage correctly handles the "username" JSON object format. DOM query scoped to app-root prevents cross-frame interference.

⚠️ Known limitation: Macro playback will send the literal string "*" to the host for password fields. A UI prompt for password re-entry at playback time is needed before macros with password steps can be used in production.

🚪 User Exits — IUserExits / AbstractUserExits / LifecycleUserExits

SAFE

The authHeader parameter removal from preConnect() is structurally consistent across all 4 layers: interface → abstract class → lifecycle implementation → event thrower. Any existing user-exit implementations that accepted authHeader will receive a TypeScript compile error pointing precisely to the incompatible signature — which is the correct and desired behavior. No silent runtime breakage.

🔄 Polling — NavigationService

SAFE

Storing the setInterval ID and adding stopHostScreenUpdate() is a pure addition — existing polling behavior is unchanged. The try/catch in errorHandler stops the interval on unexpected errors, which is the correct fail-secure behavior. No race conditions are introduced since clearInterval is idempotent.

📐 Screen Processor — ScreenProcessorService splitField()

SAFE

The bounds clamping Math.max(0, Math.min(rect.minX, content.length)) is mathematically identical to the original behavior for all valid server coordinate values (where 0 ≤ minX ≤ maxX ≤ content.length). For out-of-range server values it now silently clips instead of throwing RangeError — which preserves the screen rendering rather than crashing it.

⚙️ Configuration — ConfigurationService

SAFE (with verification note)

The APP_NAME_PATTERN = /^[a-zA-Z0-9_-]+$/ allowlist is applied to applicationName and connectionPool read from sessionConfig.json. Most ApplinX application names use only safe characters.

⚠️ Verify: If any deployed sessionConfig.json uses application names containing dots, spaces, or colons, those configurations will be silently rejected. Audit all deployment configurations before releasing.

🔧 CI Pipeline — .pipeline-config.yaml

SAFE (with prerequisite)

detect-secrets and sign-artifact steps re-enabled. npm ci replaces npm install. image_pull_policy: Always set.

⚠️ Prerequisite: npm ci requires package-lock.json to be committed to the repository. CI will fail until this file is committed. Run npm install locally to generate it, then commit.

💬 Logger — AuthTokenServerService (logger.service.ts)

SAFE

The dead getAuthToken() method removal is safe — it was never called from outside the class (confirmed by grep across all src/). The StorageService.getAuthToken() method (separate class, same name) is retained and is used by API request construction code.

🌐 AppComponent — app.component.ts DomSanitizer

SAFE

DomSanitizer is injected into AppComponent's constructor but never stored as a class field and never called. It is completely dormant — its presence causes no behavior. The basePath dead-code field removal has no effect on any template or method since the field was declared but never referenced in any binding, method call, or computed expression.

5. Incomplete Fixes Identified & Resolved

The integrity audit identified two vulnerabilities where the initial Rectifier pass applied a correct but incomplete fix — addressing one code path but missing a second independent path for the same vulnerability. Both were immediately remediated.

🔴 VULN-012 — Bearer Token: Second Injection Point in storage.service.ts

INCOMPLETE → RESOLVED

The first fix correctly removed the Authorization: Bearer header injection inside AuthTokenServerService.alterHttpRequest(). However, StorageService.setConnected() contained a second call that also sent the token:

- this.logger.setCustomHttpHeaders(
-   new HttpHeaders({ "Authorization": this.getAuthToken() })
- );

This call used NGXLogger.setCustomHttpHeaders() to push the Bearer token into the logger's global header set — bypassing alterHttpRequest() entirely. With only the first fix applied, the token could still reach the log endpoint via this second path.

Resolution:

  setConnected(authToken: string): void {
    sessionStorage.setItem('gx_token', authToken);
+   // VULN-012: Bearer token must NOT be injected into remote log requests.
+   // Header injection is fully blocked at AuthTokenServerService level
+   // (logger.service.ts). No additional header injection is needed here.
    this.router.navigate(['instant']);
  }

Additionally, the dead getAuthToken() method in AuthTokenServerService (which was now unreachable after both fixes) was removed to prevent future re-introduction risk.

Note: StorageService.getAuthToken() (a different method in a different class) was confirmed still in use and was retained.

🟡 VULN-016 — Hardcoded basePath: Second Occurrence in app.component.ts

INCOMPLETE → RESOLVED

The first fix removed basePath = 'http://localhost:2380/applinx/rest' from MacroComponent and removed three URL constants from GXUtils.ts. The audit found an identical dead-code field in AppComponent:

- basePath = 'http://localhost:2380/applinx/rest';
  observe = "body";

This field was unused in AppComponent — no method, template binding, or computed expression referenced it. However, its presence leaks the internal server URL pattern and represents the same CWE-798 / CWE-319 risk as the already-fixed occurrences.

Resolution: Field removed and replaced with an explanatory comment pointing to environment.ts.
