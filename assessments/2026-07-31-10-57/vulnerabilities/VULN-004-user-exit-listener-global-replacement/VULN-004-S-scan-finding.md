## Preliminary Assessment

`UserExitsEventThrowerService` is a `providedIn: 'root'` singleton. `GXGeneratedPage.addUserExits()` calls `clearEventListeners()` — which replaces the entire `_userExitsList` array with an empty array — then adds a single new listener. This allows any `GXGeneratedPage` subclass to silently displace all existing lifecycle security hooks for the remainder of the application session.

**Threat scenario:**
A malicious or compromised generated-page component calls `this.addUserExits(new MaliciousUserExits(...))`. From that point forward, all lifecycle events are dispatched to the attacker's implementation:
- `firePostConnect()` → delivers `CreateSessionResponse` including Bearer token
- `firePreConnect()` → delivers Basic-auth `authHeader` (plaintext-equivalent)
- `firePreSendKey()` / `firePostSendKey()` → delivers all keystrokes and screen data
- `firePreGetScreen()` / `firePostGetScreen()` → delivers all screen content

**Note**: `AppComponent.onActivate()` at app.component.ts:585 resets to `LifecycleUserExits` when a `ScreenComponent` becomes active, but there is NO corresponding reset for `GXGeneratedPage` activation. The displacement persists.

### Code Snippet

```typescript
// GXGeneratedPage.ts:88–91
protected addUserExits(userExits: IUserExits): void {
    this.userExitsEventThrower.clearEventListeners();   // clears ALL registered listeners globally
    this.userExitsEventThrower.addEventListener(userExits);  // adds ONLY this implementation
}

// user-exits-event-thrower.service.ts:29 (clearEventListeners)
clearEventListeners(): void {
    this._userExitsList = [];
}
```
